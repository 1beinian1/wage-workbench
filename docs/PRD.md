# 幸运咖兼职工资工作台 — 产品需求文档 (PRD)

## 1. 文档信息

- 版本：v1.0
- 日期：2026-08-17
- 状态：已完成需求评审（grill-me 13 轮打磨，无歧义、可执行）
- 目标设备：iPhone 17（iOS Safari PWA）

---

## 2. 背景与目标

**背景**：用户是幸运咖兼职店员，需要一个能记录每日工时、按规则计算工资、并能核对实发的轻量工具。

**工资规则**：
- 当日工资 = 当日工时（小时）× 时薪（默认 13 元/小时）
- 工资周期 = 自然月（每月 1 日至月末）
- 发薪日 = 次月 11 日发放上一完整周期工资

**产品目标**：
- 一句话：打开 app → 在日历上录工时 → 即时看到当月应发与历史周期核对情况
- 核心价值：算清工资（应发 + 实发差额）、养成录工时习惯、零运维离线可用

**非目标（本期不做）**：
- 多雇主 / 多份兼职
- 统计分析图表与多月份历史对比
- 后台推送通知（无后端）
- 云端同步 / 多端

---

## 3. 用户与使用场景

- 主用户：幸运咖兼职店员（单人，单设备）
- 场景 A（每日录工时）：下班后打开 app，在日历点今天，填工时，看到当日工资与当月累计应发
- 场景 B（补录/改）：发现漏记某天，点过去某日补录；或修正误填
- 场景 C（发薪日核对）：11 号打开 app，提醒发薪，进入工资 Tab 录入实发，与应发对比
- 场景 D（换机/重装）：从设置导出 JSON，新设备导入恢复

## 4. 核心功能模块（MVP 必做）

每个模块给出：输入 / 输出 / 交互逻辑。

### C1 每日工时录入与编辑

- **输入**：选定日期（默认今天）、工时小时数（0–24，0.1 精度）、可选标签（加班/调休）、可选备注
- **输出**：一条 `workRecord`（含 `rate` 快照）；当日工资 = `hours × rate`；当月应发实时更新
- **交互**：日历点日 → 下方编辑卡出现 → 数字键盘输入工时 + ±0.1 步进按钮 → 可加标签/备注 → 失焦自动保存；过去日可改、不锁定；清空工时即将该日转为休息或删除记录
- **校验**：`0 ≤ hours ≤ 24`，超限报错；`hours=0` 且未标休息 = 漏记态、不计薪
- **规则**：时薪取当前 `settings.hourlyRate` 并**快照写入 `rate`**；改设置只影响此后新建记录

### C2 日历视图展示（首页）

- **输入**：月份（默认当月）、各日 `workRecords`
- **输出**：月历网格 + 顶部当月汇总 + 下方当日详情/编辑卡
- **交互**：顶部左右箭头或左右滑切换月份；单元格显示日期号 + 工时数 + 状态色；点日 → 下方卡片切换该日、就地编辑不跳页；顶部汇总 = 已录天数（`hours>0`）/ 总工时 / 应发
- **单元格状态色**：工作日（有工时，主色）/ 休息（显示"休"）/ 漏记（过去日无记录，淡色"未录"）/ 今日（高亮描边）/ 未来日（灰）

### C3 月度工资汇总

- **输入**：指定周期（年月）的 `workRecords`
- **输出**：该周期应发 = `Σ(hours × rate)` 实时算；已录天数；总工时；日均工时
- **交互**：首页顶部展示当月汇总；工资 Tab 展示各周期列表
- **规则**：只统计 `hours>0` 的记录；休息不计薪

### C4 工资周期与发薪日提醒（应用内）

- **输入**：当前日期、`settings.payday`、各周期 `isPaid`
- **输出**：顶部横幅 / 红点提醒
- **触发条件**：
  - 今天日号 == `settings.payday` 且上一周期（`periodKey = 上月`）未标已发 → "今天是发薪日，去核对实发"
  - 过去 N 天（默认 3）存在漏记（无记录且未标休息）→ "X 天未录工时"
- **交互**：打开 app 时检查；点横幅跳转对应视图（工资 Tab / 日历补录）
- **约束**：纯前端、不开后端推送；关闭 app 不触发通知（接受此代价）

### C5 工资周期核对实发

- **输入**：选定周期、实发金额（可选）、"标记已发"操作
- **输出**：`payCycle` 记录（`actualWage` / `isPaid` / `paidAt`）；差额 = 应发 − 实发
- **交互**：工资 Tab 列表点开某周期 → 显示应发（实时）+ 实发输入框（可选）+ "标记已发"按钮；差额正负标色
- **规则**：应发实时算；标已发后若改记录，应发会变、差额随之变化（可揭示补录）；实发可留空（仅跟踪应发）

### C6 设置

- **输入**：时薪（默认 13）、发薪日（默认 11）
- **输出**：`settings` 单条记录
- **交互**：数字输入修改，即时保存；改时薪只影响此后新建记录的 `rate` 快照
- **规则**：工资周期（自然月）硬编码、不可改

### C7 数据导出与导入（JSON 全量）

- **输入**：导出按钮 / 导入文件
- **输出**：导出 = 含全部 `workRecords` + `payCycles` + `settings` 的 JSON 文件；导入 = 覆盖本地同日期数据
- **交互**：设置页导出 → 保存文件；导入 → 选 JSON → 预览受影响天数 → 确认覆盖
- **规则**：导入同日期覆盖（以导入数据为准）；全量备份/恢复语义
- **存储安全**：启动调 `navigator.storage.persist()` 申请持久化，降低被 iOS 清理风险

### C8 iOS PWA 安装与离线

- **安装**：Safari → 分享 → 添加到主屏幕；浏览器态（非 `standalone`）首次访问弹"添加到主屏幕"引导横幅（可关闭）
- **离线**：Service Worker 预缓存 app 外壳；无后端 → 离线即完整可用
- 详见第 8 节 iOS PWA 适配要求

## 6. 数据存储结构（IndexedDB）

数据库名：`wage-workbench`（版本 1）

### 6.1 store: `workRecords`（每日工时记录）

- **主键**：`date`（string，`'YYYY-MM-DD'`，用户工作的本地日历日期，无时分、无时区）
- **字段**：
  - `date`: string，主键
  - `hours`: number，0–24，精度 0.1
  - `rate`: number，录入时时薪快照（取 `settings.hourlyRate`）
  - `isRest`: boolean，默认 `false`；`true` = 休息标记（此时 `hours` 应为 0）
  - `tags`: string[]，标签集合，取值 `'加班'` / `'调休'`（纯标记，不影响工资）
  - `note`: string，可选备注
  - `createdAt`: number（timestamp）
  - `updatedAt`: number（timestamp）
- **索引**：
  - `by_period`：派生自 `date` 前 7 位 `'YYYY-MM'`，用于按月汇总查询
- **约束**：
  - `0 ≤ hours ≤ 24`
  - `isRest=true` 时 `hours` 应为 0
  - `hours=0` 且 `isRest=false` = 漏记态（不计薪）

### 6.2 store: `payCycles`（工资周期）

- **主键**：`periodKey`（string，`'YYYY-MM'`，该周期起始月）
- **字段**：
  - `periodKey`: string，主键
  - `actualWage`: number | null，实发金额，用户录入（可空）
  - `isPaid`: boolean，默认 `false`
  - `payday`: string，发薪日 ISO `'YYYY-MM-DD'`（= 次月 `settings.payday` 日，由设置推导）
  - `paidAt`: number | null，标记已发时间戳
- **索引**：主键即可
- **规则**：**应发不存、实时算** = 对 `workRecords` 中 `by_period == periodKey` 且 `hours>0` 的记录求 `Σ(hours × rate)`
- 周期记录**按需懒创建**（首次核对/标记时建）

### 6.3 store: `settings`（配置）

- **主键**：`id`，固定单条 `id='app'`
- **字段**：
  - `id`: `'app'`
  - `hourlyRate`: number，默认 13
  - `payday`: number，默认 11（每月发薪日）
  - `schemaVersion`: number，数据结构版本（便于后续迁移）
  - `updatedAt`: number

### 6.4 典型查询模式

- 当月汇总：`workRecords.index('by_period').getAll(currentPeriod)`
- 周期应发：上同 + `reduce Σ(hours × rate)`，仅 `hours>0`
- 漏记检测：从今日往前遍历 N 天，`workRecords.get(date)` 不存在且非休息标记 → 漏记
- 发薪日判断：`today.day == settings.payday` 且对应上一周期 `isPaid == false`

## 7. 页面/视图划分与导航

### 7.1 视图（底部 3-Tab，iOS 风）

1. **日历（首页）**
   - 顶部：月份标题 + 左右切换 + 当月汇总条（天数 / 总工时 / 应发）
   - 中部：月历网格（7 列 × 5/6 行）
   - 下部：当日详情/编辑卡（点日切换）
2. **工资**
   - 周期列表（按月倒序），每行：年月 / 应发（实时）/ 实发 / 状态徽标（待发/已发）
   - 点开周期 → 详情：应发明细 + 实发输入 + 标记已发
3. **设置**
   - 时薪、发薪日、数据导出（JSON）、数据导入、关于
   - 可选：导出提醒到 iOS 系统提醒（P3）

### 7.2 导航逻辑

- 底部 Tab 固定，`env(safe-area-inset-bottom)` 留白避让 Home 手势条
- Tab 间切换无边缘滑动（Tab 为平级）
- 日历内月份切换：顶部箭头或左右滑
- 点日就地展开编辑卡，不跳页
- 跨视图跳转：横幅提醒点击 → 跳对应 Tab/周期

### 7.3 状态

- 首次浏览器访问（非 `standalone`）：顶部弹"添加到主屏幕"引导（可关闭）
- 空状态（无任何记录）：日历空网格 + 引导"点今天录第一笔工时"
- 安装态（`standalone`）：无引导横幅，直接进入

| 项 | 要求 |

| 存储 | 启动调 `navigator.storage.persist()` 申请持久化 |
| 手势 | 安装态禁双指缩放贴近原生；防橡皮筋滚动；固定字号 |
| 安装引导 | 浏览器态（非 `standalone`）首次访问弹引导横幅 |

## 9. 非功能需求

- **性能**：首屏（日历）打开 < 1s（本地数据）；IndexedDB 查询走 `by_period` 索引
- **离线**：100% 功能离线可用（无网络依赖）
- **数据安全**：`persist()` 申请 + JSON 备份；提示用户定期导出
- **单设备单用户**：无账号、无鉴权
- **兼容**：iOS 16.4+；目标 iPhone 17
- **包体积**：控制首屏资源，图表/重依赖本期不引入

---

## 10. 范围外（本期不做）

- 云端同步 / 多端

## 11. 关键验收场景

1. 录入今天 8.0h → 日历今日格显示 8.0，顶部应发 +¥104.00，工资 Tab 当月周期应发 ¥104.00
2. 改时薪 13→14 → 历史记录工资不变（快照 13），新建记录按 14
3. 标记某天休息 → 日历显示"休"，不计入应发，不算漏记
4. 漏记昨天 → 今日打开 app，顶部提醒"1 天未录工时"
5. 11 号打开 → 提醒发薪 → 工资 Tab 录入实发 3000 → 应发 3100 显示差额 +100
6. 标已发后补录一天 → 应发变 3226，差额变 +226（揭示补录）
7. 导出 JSON → 清空数据 → 导入 → 全部恢复，同日期覆盖生效
8. Safari 添加到主屏幕 → 全屏无地址栏，离线打开正常
9. 飞行模式下打开 → 全部功能可用
